# AirMate CN 本地 MQTT 改造方案

状态：开关、调速、水平/垂直摇头已实现，已通过统一验收前的真实 HA 复核，可以统一验收。基于原仓库 `b2a08ea`，2026-10-27。

实现与安装见 [README.md](../README.md)，测试结果及验收清单见 [ACCEPTANCE.md](ACCEPTANCE.md)。

## 1. 目标与范围

在原厂 App/API 不可用时，通过自建 MQTT broker 接入风扇，继续在 Home Assistant 中使用。
保留设备固件内的 `xiot.zhidekan.tv`，由用户配置 DNS 指向 broker，不改固件。

本轮交付：本地集成代码、配置界面、中文/英文文案、必要的回归测试、安装与验收说明。
先完成隔离环境验证，再由使用者按部署指南部署。
不要修改与本集成无关的 DNS、防火墙、路由或代理配置。

## 3. 部署结构

```text
风扇 ── MQTT 3866 ── Mosquitto ── HA MQTT 集成 ── AirMate CN
       原域名由用户 DNS 指向 broker
```

- broker 应作为独立服务维护，可使用 Docker Compose 或系统服务。
- 独立调试应使用隔离的 Compose 服务，不重启现有 Home Assistant。
- 正式部署时让 DNS 指向 broker 主机的局域网地址。
- 风扇保留原鉴权，HA 使用单独账号；ACL 只开放已确认的 data/rrpc 主题。
- 密码、原始 CONNECT、抓包和设备标识文件只保存在忽略目录，不提交 Git。

## 4. 插件结构

### 协议层

新增独立于 HA 的协议模块，负责：

- 校验 product/device 标识及 topic，拒绝跨设备、畸形 JSON、非法字段值。
- 区分基础信息、定时信息和属性上报，忽略不认识的消息。
- 合并部分状态，不把缺失字段设成 0；保留最后确认值。
- 编码已验证的控制消息，生成不重复的 msg_id 和毫秒 timestamp。
- 写入字段与上报字段可以不同，不能在实体层假设完全对称。

### MQTT 与状态管理

通过 HA 官方 MQTT API 订阅/发布，不内嵌 broker、不自建 paho 连接。
每个配置项对应一台风扇，使用 `entry.runtime_data` 存储运行对象。

- 初始化不调用原厂登录/设备列表，等待实际 MQTT 上报。
- 使用推送式 coordinator，移除 2.5 小时轮询和 120 秒缓存。
- 命令 `retain=false`；默认 QoS 0，不自动重发物理命令。调速使用两个预先确定的协议步骤，不是重试。
- 命令按设备串行处理（包含整个两步调速），只在最终步骤之后的新设备状态匹配后认定生效。
- 两步间连接状态变化，即使已经重连，也中止本次后续命令；不跨连接续发半完成事务。
- 不先修改本地状态伪装成功；发布失败/确认超时向 HA 返回明确错误。
- broker 断开或超过 180 秒设备消息超时后标记不可用；收到新消息后恢复。
- 无 will 的设备不假定存在 availability topic；不把 broker 在线等同于风扇在线。
- 卸载时取消订阅、定时器、连接状态监听及等待中的命令。

### 配置与迁移

- 配置前需先配置 HA 的 MQTT 集成。
- 用户输入产品 ID、设备 ID 和名称；也可通过观察器获得，界面不要求原厂账号密码。
- 稳定唯一标识以产品 ID + 设备 ID 去重；实体与 device registry 标识尽量沿用旧设备 ID。
- 旧云端配置不静默转换成缺少身份字段的本地配置；给出明确的重新配置步骤。
- 不删除旧源码历史；新版本入口以本地模式为主，避免继续调用失效云 API。

### 实体

- 风扇：开关、32档百分比调速、水平摇头；0% 单独关机。普通开机保留当前档位。
- 水平 select：只允许 off/30°/60°/90°，对应0/2/3/4；收到1时不伪装为合法选择项。
- 垂直 switch：0/1开关。主风扇、select、switch沿用旧 unique_id。
- 六个原始状态传感器保留；模式、灯光、静音仍不开放单独控制。
- 未上报属性显示 unknown，设备断连/过期显示 unavailable。

## 5. 原实现问题及处理

| 原问题 | 改造要求 |
| --- | --- |
| 风速 0 会调用开机逻辑 | 单独处理 0%，编码 power_switch=0 |
| select 回填 True/False | 显式映射上报数字到合法 option |
| 发命令前更新缓存且失败不回滚 | 以设备推送为状态来源，命令等待确认 |
| 2.5 小时轮询、120 秒缓存 | 改为 MQTT 推送，不依赖云轮询 |
| 原厂认证与实体耦合 | 本地协议和 HA 实体分层 |
| 临时属性 entry.coordinator | 使用 runtime_data 并提供完整卸载路径 |
| 假脱敏函数/调试日志 | 不记录原始鉴权/完整业务 payload，诊断输出脱敏 |

## 6. 测试与验收

### 自动化

1. 协议：完整/增量消息合并，无 method 的合法消息，错误 topic/设备 ID，畸形/越界值。
2. 控制：retain=false，命令参数正确，fresh report 确认，错误/超时不伪造状态。
3. 实体：开/关、全部32档的百分比往返换算、0%关机、未知值、select枚举及switch写入。
   测试两步调速的发送顺序、最终确认、新消息与准备阶段消息隔离、中途断连中止及失败不重发。
4. 生命周期：重连、消息超时、恢复、卸载取消订阅与等待任务。
5. HA 兼容：使用已验证的 Home Assistant 2026.10.2 验证导入、配置流程和隔离测试环境。

### 实机

- 开关已通过真实MQTT与HA服务验证。
- 调速已确认9/10/11/12档，两步流程连续11→10→12→11通过；不把之前单包“未确认”判为绝无效果。
- 水平0/2/3/4、垂直0/1已收到匹配新回报，历史恢复参考水平30°/垂直关已新确认。
- HA统一复核包括百分比调速、水平角度选择、垂直开关及0%关机，记录见ACCEPTANCE.md。
- 用户目前不在实物前，机械动作与角度仍由用户最终目视验收。

### 用户验收

- 按 README 在测试 HA 安装，配置 MQTT 与 AirMate 本地条目。
- 上报在 HA 中出现，手动遥控/面板改变后 HA 同步（仅按已观察到的上报能力承诺）。
- 已启用的控制有设备回报，失败有错误提示。
- HA/broker 重启后能重新连接，无 retained 旧命令重放。
- 无原厂 HTTP 登录请求，无新增路由器修改，无敏感信息进入 Git。

## 8. 实现结论与剩余边界

本版为 fan + select + switch + 六个状态sensor，删除云登录/HTTP/旧轮询缓存。
命令超时15秒，设备消息过期180秒。已确认目标同值时跳过发送；未知电源状态下重复设置
当前已处于的值可能没有新上报，此时明确超时。集成不自动开关来填充初始化状态。

两步调速是实验中可重复通过的应用流程；内部固件处理原因尚未通过固件/串口证据确定。
需要标准风参数，不承诺婴儿风/暴风切换已验证。其余未解决问题包括主动全量查询、
模式/灯光/静音单独控制，以及其他型号/固件的兼容性。正式部署在统一验收之后按部署指南进行。
